NGelectionpolls eyewitness registration feed

Prepared, not installed or published. ASIF's Hero is ready. Real registrations will appear after the new feed is added to the separate NGelectionpolls backend.

Download backend endpoint package

What it uses

The existing MongoDB database, User model, and coverage registry on NGelectionpolls. No new database, credentials, migrations, dependencies, or record changes are needed.

Installation

  1. Extract the package. It contains a README and one new backend route.
  2. Add src/app/api/recent-eyewitness-registrations/route.ts to the existing NGelectionpolls source. Do not overwrite existing routes.
  3. Run the NGelectionpolls backend's build and tests. This route has been tested here with simulated data, not against live MongoDB.
  4. Confirm the platform's privacy notice and permissions allow public first-name/initial activity displays.
  5. Only when separately authorized to release that backend change, check that its recent-registration endpoint returns HTTP 200.
  6. The ASIF preview will detect the feed automatically on its next refresh, within 30 seconds.

ASIF has not been published. Do not publish it without separate approval.

Display and privacy

The feed returns up to 15 newest eligible eyewitness account registrations: registration time, first name, surname initial, and assigned state only. Eligibility uses completed biodata and matched state/LGA/ward coverage locations, as on the map. Account creation time is used because a separate profile-completion or state-assignment timestamp is not stored in the uploaded model.

No full surnames, emails, phone numbers, account IDs, exact polling locations, identity documents, photos, or banking details are exposed. First names and initials are still personal data, so confirm that the intended public display is permitted before activation.

Until the endpoint is available, ASIF displays an unavailable message with retry. It never substitutes sample registrations or labels unavailable data as live.
